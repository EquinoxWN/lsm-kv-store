# Quality check, 2026-11-01

The owner's 10 rules, checked against the code on Windows 11 with Go 1.26.10. The race detector
needs cgo, which this machine lacks; CI runs `make test` with `-race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | No network calls; all I/O is local files. Every file error is returned (`lsm.go`, `wal.go`, `sstable/*.go`); the ignored ones are cleanup after an earlier error (`os.Remove(tmp)` in `writeTable`, `Abort`) and the log delete after a flush (`lsm.go` `flushLoop`, commented: recovery skips records already in tables, tested by `TestLeftoverLogOfFlushedWritesIsNotFlushedAgain`). A WAL append failure stops all writes (`bgErr`). Defect fixed: `sstable.load` checked `off+len+crc > end` in uint64, so a footer with a huge length wrapped around, passed, and `readBlock` panicked with a slice-bounds error; it now uses an overflow-safe `within` check (`internal/sstable/reader.go`), test `TestFooterLengthsThatOverflowAreRejected`. |
| 2 | Writes safe to retry | pass | Tables are written to `.tmp`, fsynced and renamed (`writeTable`); leftover `.tmp` files are deleted on open. Replaying a log whose records are already in a table is skipped by sequence number (`recover`, `r.Seq > tableSeq`), now covered by a test that restores such a log and asserts one table. A repeated `Put` of the same key writes a newer version, which is the intended semantics. |
| 3 | No race conditions | pass | Shared state (`mem`, `imm`, `tables`, `seq`, `bgErr`, `closed`) is read and written under `db.mu`; `tables` is replaced, never mutated in place; `readMu` keeps `Close` from closing files under a reader. `TestConcurrentReadersAndWriters` (8 writers, 8 readers) runs with `-race` in CI. |
| 4 | Don't trust the clock | N/A | No durations or timestamps in the store; ordering uses sequence numbers. Benchmarks use `testing.B`. |
| 5 | Read before changing | pass | No environment variables or config files are read; the CLI's only flag is `-dir`. Paths named in the README exist. |
| 6 | Never break compatibility | pass | WAL and SSTable formats unchanged; the fix only rejects footers that could never have been written. |
| 7 | One source of truth | pass | Tables and logs are the only state; the memtable is rebuilt from the WAL on open. No caches. CI and the README both name Go 1.26.10; `go.mod` states only the minimum language version (`go 1.23`). |
| 8 | Small changes, no secrets, validate input | pass | No secrets. Inputs: empty keys and entries over 32 MiB are refused, the CLI checks the command and its argument count (now tested, `cmd/lsm-kv-store/main_test.go`), WAL records and SSTable blocks are checksummed, WAL lengths over 64 MiB are refused before allocation (now tested). No new dependency. |
| 9 | Tests that can actually fail | fixed | No skips or tautologies. Mutation check below: 9 survivors before, 7 now have killing tests, 2 are equivalent in-process. |
| 10 | Re-verify | pass | `gofmt -l .`: no files; `go vet ./...`: clean; `go test -count=1 -v ./...`: 34 passed, 0 failed; `govulncheck@v1.8.0 ./...`: No vulnerabilities found; `audit_repo.py lsm-kv-store`: OK. CI result in `docs/results/m1.md`. |

Known limitation (unchanged, by design): WAL replay stops at the first bad record and treats the rest
of that log as a torn tail, so a corrupted record in the middle of a log also drops the records
after it. This matches LevelDB's default recovery mode; detecting mid-log corruption would need a
per-record recovery mode and is out of scope for M1.
